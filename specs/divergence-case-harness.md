# Divergence Case Harness

<!-- spec:planned-at 7314bfc6c6fd04ee21f480feca17692d14639268 2026-09-04 -->

## Overview

Every divergence this project finds between a transpiled rule and its PHPStan original is recorded as prose
in `VERIFICATION.md` and nowhere else. Nothing re-runs it, so a divergence cannot be re-checked later — two
have already been lost to version drift. This adds a permanent, minimal, committed case per divergence,
batched into one run, recorded in one file that a test diffs.

Rule drift is already covered — `LockedCorpus` pins seven packages, `census.md` records every rule's outcome
and the versions it was recorded against, `TracksUpstreamDriftTest` fails on change. This is the same
mechanism for the other axis: what the two engines *say about code*.

## Assumptions

Carried from the interview. **Not grilled item-by-item** — the user moved to implementation before the audit
ran, so these are recorded as inferences rather than confirmations.

- **Cases boot both engines.** Implied by the ~13s-per-case figure the user saw when choosing the run model.
  Low risk.
- **Engine versions are recorded in the file.** Assumed, not asked. `census.md` sets the precedent and this
  session lost two findings to unrecorded versions.
- **`TraitDivergence` migrates into the new mechanism.** Assumed, not asked. It could equally stay as its own
  test.
- **Nothing is replaced.** `run-corpus-differential.php`, the fires gate and the census all remain.
- **Case directory naming** (`tests/Fixtures/Divergence/<name>/`) is a spec-body detail, not a decision.
- **Load-bearing, user-accepted:** cases must not interfere under one engine boot. Measured from both
  directions in this repository. See §2 and STOP condition 1.

## 1. Why prose is not enough

Three failures, all from this project's own history:

- **`Benchmark.php:27`** — recorded as a template-inference divergence. Re-checked later, both engines read
  `mixed` and agree. Why the original run reported one-sided could not be established, because the corpus was
  a Laravel version nobody captured. The cause is now marked permanently unknown.
- **`QueueFake.php`** — the same finding appears as `:214` in one entry and `:167` in a later run. Version
  drift, invisible until two entries were read side by side.
- **Three ad-hoc sweeps in one session produced zero data.** Each was a hand-rolled shell script; each failed
  on `PATH` inside a `nohup`'d subprocess. The harness being rebuilt per question *is* the gap.

Prior art, read from `phpstan-src`: PHPStan solves this with **`e2e/`** — 113 tiny pinned projects, one per
reported bug, typically a `phpstan.neon` plus one or two PHP files, committed and permanent. Its large-corpus
mechanism (`issue-bot/`) is deliberately *not* pinned: it re-fetches playground examples and issues, caches
them, and shards CI by PHP version. Breadth comes from many small pinned cases, not from few large trees.

## 2. What a case is

A directory under `tests/Fixtures/Divergence/<name>/` holding:

    subject/          the PHP the two engines disagree (or agree) about
    case.neon         which rule to run, and any scanFiles the subject needs
    README.md         the written cause, and for a synthesised case, which real finding it stands for

No case declares its expected result. Results live in one recorded file (§3), so adding a case is adding a
directory — the runner needs no change.

**Cases must not interfere.** They share one engine boot, and this repository has measured interference from
both directions: a trait with no using class in scope changes what PHPStan reports about it (19 of 28
recorded divergences are exactly this), and narrowing a corpus to one directory turned every finding into
`trait.unused`. Therefore each case gets its own namespace, and a case whose subject references an
unresolvable parent must not put that parent where another case resolves it. This is the cost of batching and
is accepted deliberately.

## 3. The recorded file

One file, `tests/Fixtures/expected/divergences.md`, generated by the runner and asserted by a test, in the
shape `census.md` already uses: a header stating what generated it and against which versions, then one
section per case.

    # Divergence cases
    
    GENERATED by tests/Unit/RecordsDivergencesTest.php. Do not edit by hand.
    Recorded against: mago 1.47.6, PHPStan 2.2.13
    
    ## callable-string-refinement        AGREE
        both      Subject.php:12   symplify.noDynamicName
    
    ## closure-array-suffix              DIVERGE
        original  Subject.php:9    strict.callableReturn
        port      —

**The versions matter and are not decoration.** `census.md` records package versions for the same reason, and
this session lost two findings to unrecorded versions. A version change that moves a case shows up as a diff
with the version line changed in the same commit.

**A case asserting agreement is not automatically evidence.** This project's own rule — *agreement on zero is
not evidence* — applies here: a case where both engines report nothing is consistent with "they agree" and
with "neither looked". Every case must therefore record at least one finding on at least one side, and the
runner fails a case that records nothing at all.

## 4. Suite split

`composer test` currently runs everything, ~250-330s, of which `EmittedRuleFiresTest` is 564 tests and ~180s.
Split by whether a check boots a subprocess:

| script | contains |
|---|---|
| `composer test` | everything needing no engine subprocess |
| `composer test-full` | the above plus the fires gate, the divergence batch, the aggregates, the drift census |

**This is the main risk in the change.** The fires gate is this repository's answer to its own rule *"'It
emitted' is not a result"* — a bare snake_case identifier is valid PHP and only execution catches it. Moving
it out of the default run relocates that guarantee; it weakens it unless CI runs the full suite on **every
push**. `.github/workflows/run-tests.yml` must therefore call `test-full`, not `test`.

`.github/workflows/upstream-parity.yml` already exists — nightly, matrix over `released` and `dev-main`
corpus legs, listing corpus versions and diffing the census. The divergence batch belongs there too, so an
upstream release that moves a case is caught nightly rather than at the next push.

## Edge Cases

| Scenario | Handling |
|----------|----------|
| A case's subject does not parse | The runner fails that case by name rather than recording an empty result — a parse failure is indistinguishable from agreement in the output otherwise. Covered by Phase `runner` Tests. |
| Two cases declare the same namespace | The runner refuses before booting either engine, naming both cases. Interference is silent otherwise. Covered by Phase `runner` Tests. |
| One case's unresolvable parent changes another case's findings | Prevented by per-case namespaces and the no-shared-parents rule in §2; asserted by a case pair that would collide if the rule were dropped. Covered by Phase `cases` Tests. |
| A case records no finding on either side | The runner fails it. Agreement on nothing is not evidence, and a case that stops exercising its rule would otherwise go green forever. Covered by Phase `runner` Tests. |
| The mago binary is absent | The full suite fails rather than skips. A skipping test's green is uninformative — this repository has recorded that failure mode — and the full suite is the one place a missing binary must be loud. |
| An engine version changes and moves a case | The recorded file diffs, with the version header changing in the same commit, so a reviewer sees cause and effect together. |
| A case is added without regenerating the file | The assertion fails, naming the case present on disk and absent from the record. |
| A rule a case names stops emitting | The runner fails that case rather than recording "port: —", which would read as a divergence rather than a broken case. Covered by Phase `cases` Tests. |

## STOP Conditions

Stop and report — do not improvise — if any of these proves false during implementation:

1. **Cases can share one engine boot without interfering.** If two cases' findings change when run together
   versus alone, batching is unsound for this corpus and the run model needs revisiting — do not paper over it
   by isolating the offending case silently.
2. **A rule can be run against an arbitrary subject directory.** The runner assumes the fires gate's sandbox
   approach generalises. If a case needs configuration the harness cannot express, stop rather than special-casing.
3. **The default suite can be made subprocess-free.** If a test outside the named group boots an engine
   indirectly, the split criterion is wrong and the boundary needs re-deciding, not widening quietly.

## Open Questions

1. **The large-corpus runner is deferred, not designed.** The interview settled "both mechanisms, cases
   first". This spec covers only the cases. The second half — a committed multi-corpus, multi-variant runner
   with recorded baselines — needs its own design, and the recorded-file format here is meant to be the
   baseline shape it reuses. Whether corpora are pinned, re-fetched (as `issue-bot` does), or supplied per run
   is unresolved.
2. **Whether the divergence batch runs in `upstream-parity.yml` as well as on push.** §4 argues it should, so
   an upstream release that moves a case is caught nightly. Not confirmed with the user.
